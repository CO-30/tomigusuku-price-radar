# TOMIGUSUKU PRICE RADAR 設計書

日付: 2026-11-19 / 作成: Claude（プロジェクト指示に基づく自律開発）

## 1. 意図と背景

沖縄県豊見城市周辺のスーパーの特売情報を毎朝自動収集し、容量・個数を解析して
**実質単価（¥/100g・¥/100ml・¥/個 等）の安い順**に横断比較するWebアプリ。
ユーザーは毎朝スマホで開くだけで「今日どこで何を買うのが本当に得か」が分かる。

- 完全無料運用（新規契約・課金・有料API一切なし）が絶対条件。
- 個人利用。毎朝7時(JST)までに自動更新。

## 2. 調査で確定した外部制約（2026-11-19 時点）

| 取得元 | 状況 | 判断 |
|---|---|---|
| トクバイ (tokubai.co.jp) | 沖縄主要チェーンのWebチラシが集約されているが、robots.txt が AI クローラーを全面拒否 | **自動収集しない** |
| ユニオン / かねひで / ダイレックス / 業務スーパー 公式 | robots.txt によりクローラー拒否を確認 | 自動収集しない（手動補完対象） |
| サンエー / リウボウ 公式 | Bot アクセスを拒否（403） | 同上 |
| イオン琉球 公式 (aeon-ryukyu.jp) | サイト自体は取得可。ただしチラシ本体はトクバイwidget埋め込み | 店舗情報のみ利用 |
| 開発サンドボックス | pypi/npm/GitHub 以外への外向き通信不可 | 実収集の検証は GitHub Actions 上で行う |

→ **「取得できない店舗を無理に処理しない」原則に従い、収集は実行時に robots.txt を
自動判定して許可されたもののみ**。加えて**手動アップロード（チラシ撮影/スクショを
inbox に投入 → 同一パイプラインで OCR 解析）を第一級の入力経路**とする。
新聞折込チラシ・店頭チラシの撮影画像が現実的な主力データ源。

## 3. ゴール / 非ゴール / アンチゴール

- ゴール: 毎朝7時に最新ランキング・チラシ画像・価格履歴・買い物リストが揃っている。
  取得状況（店舗別の成功/失敗/未対応/手動）が常に明示される。
- 非ゴール: 店舗数の最大化、全商品網羅、リアルタイム更新。
- アンチゴール: 規約違反スクレイピング、推測による価格・容量の捏造、課金発生。
  不確かな情報は「要確認」表示にし、重量不明なら単価を計算しない。

## 4. アーキテクチャ

```
GitHub Actions (cron 20:30 UTC = 05:30 JST, retry 21:30 UTC)
  collector/  robots判定 → 許可ソースのみ取得 + inbox/ の手動投入を取込
  analyzer/   PyMuPDF/OpenCV/Tesseract(jpn) OCR → 価格アンカー方式で商品抽出
              → 容量・税・条件パース → 辞書分類 → 単価計算 → 信頼度付与
  storage/    SQLite (data/radar.sqlite, リポジトリにコミット=無料永続化+履歴)
  export      data/public/*.json (ランキング・履歴・店舗状況)
  deploy      Vite build → GitHub Pages
frontend/ (React+Vite+TS, モバイル最優先, 状態はlocalStorage)
```

- 技術: Python 3.12+, pytesseract+Tesseract5(jpn/jpn_vert), OpenCV, PyMuPDF,
  PyYAML, requests, pytest / React 18 + Vite + TypeScript（外部UIライブラリなし）
- 通知: フロントエンドで目標価格以下を検知してバッジ/一覧表示（無料・インフラ不要）。
- バックアップ: SQLite も JSON もリポジトリにコミットされるため git 履歴が完全バックアップ。

## 5. 主要な設計決定

1. **robots.txt 実行時判定**: 各ソースの取得可否は収集のたびに urllib.robotparser で
   判定（UA: `TomigusukuPriceRadar/1.0 (personal; +repo URL)`）。拒否 → 店舗状態
   `blocked`。固定リストで規約を破る事故を構造的に防ぐ。
2. **価格アンカー抽出**: OCR 結果（単語+座標）から「価格らしきトークン」
   （例: `198円`, `¥98`, `105.84`）を見つけ、近傍の語を商品ブロックとして束ねる。
   チラシは非定型なのでレイアウト解析より頑健。
3. **単価計算は保守的に**: 容量が確実にパースできた場合のみ計算。
   比較単位は食品分類ごとに固定（野菜果物=100g, 卵=1個, 牛乳=100ml, 米=1kg,
   豆腐/納豆/ヨーグルト=100g, その他=100g/100ml/1個）。
4. **税**: 税込表記を優先。税抜のみなら食品8%で税込換算し `tax: estimated` を付与。
5. **信頼度**: price/quantity/name 各信頼度の積。しきい値未満は「要確認」で
   ランキング対象外（別リストに表示）。
6. **店舗状態**: ok / failed / blocked / no_flyer / unsupported / manual を毎日記録。
7. **手動投入**: `inbox/<store_id>/` に画像/PDFを置く（スマホからは GitHub web UI で
   アップロード可能）。ファイル名 `YYYY-MM-DD_期間末日.jpg` 形式なら特売期間に反映。

## 6. 検討した代替案

- **トクバイ/Shufooのスクレイピング**: 情報量は最大だが robots/規約違反 → 却下。
- **有料チラシAPI・LLM API での解析**: 完全無料の絶対条件に反する → 却下。
- **Supabase 等外部DB**: 新規契約が必要 → 却下。SQLite+git で十分。
- **ローカルPC常駐実行**: Claude Desktop が閉じても動く要件は満たすがPC電源依存
  → GitHub Actions（既存無料枠, public repoは無制限）を第一とする。

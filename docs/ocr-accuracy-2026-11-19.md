# 実物チラシ画像でのOCR精度検証（2026-11-19）

## 検証対象
ザ・ビッグエクスプレスつかざん店 2026/11/18-19 チラシを、スマートフォンで
トクバイ掲載ページを表示してスクリーンショットした画像1枚（1170x2532px）。
※撮影者の端末でカラーフィルタ（アクセシビリティ設定）が有効だった。

正解データ: 目視で読み取れた本体価格19件
`47, 57, 77, 87, 97, 107, 117, 127, 137, 147, 157, 217, 257, 277, 297, 797, 1470, 1770, 3970`

## 結果

| 前処理 | 価格の読み取り |
|---|---|
| 現行（BGR2GRAY + 2500px拡大 + デノイズ） | 3/19 |
| 最大分散チャンネル + CLAHE | 3/19 |
| 同 + デノイズ | 1/19 |
| 同 4000px拡大 | 3/19 |
| グレースケールのみ・デノイズなし | 3/19 |
| タイル分割（3x6・各2400px） | 7/19 ※image_to_string経由、再現せず |

商品名は全件破綻（近傍語が結合し意味をなさない文字列になる）。

## 判明した本質的な原因
**拡大しても読めない。** 商品セルを切り出して2000pxに拡大しても、
大きな特価数字（47円・57円・277円）は1件も読めなかった。
一方で同じ切り出し画像の中の「11/18」「限定600点限り」といった
**小さな通常フォントの文字は読めている**。

つまり解像度不足ではなく、**日本語チラシの特価数字が
縁取り・影付きの装飾フォントで爆発型の背景に重なっている**ことが原因で、
Tesseractの学習データの範囲外にある。前処理のチューニングでは解決しない。

## 結論
- チラシ全面のスクショからの自動抽出は実用水準に達しない（価格で約16%）。
- 「拡大して撮る」という回避策も効かない（装飾フォントの問題のため）。
- OCRは補助に留め、**手入力を一次手段として設計し直す必要がある**。
  単価計算・価格履歴・横断比較というシステムの価値は、入力さえあれば成立する。

## 再現方法
`analyzer.ocr.ocr_image()` に対象画像を渡し、抽出語に含まれる2〜4桁の数字と
上記正解データを突き合わせる。検証スクリプトは本番コードに含めていない。
